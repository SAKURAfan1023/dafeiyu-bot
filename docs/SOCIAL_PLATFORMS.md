# 社交平台：共享引擎与 B 站接入

版本：2026-10-28 · AI 实施版。调研档案 `20261028-social-platforms`，初始源码 `cc81703`。

## 上下文与决定

客户端目录调整为 QQ → 社交平台 → 微信。社交平台下面选择小红书、B 站，再在共用页面切换连接、浏览、草稿和指南。后续平台沿用这层分类。

共享人格预设、模型凭证访问、任务/草稿/记忆代码和 Web 资源；每个平台有自己的引擎实例、浏览器 Profile、账号、任务、额度、记忆和警告暂停状态。模型地址与名称可各自选择，已保存的同服务 Key 共用，运行期临时 Key 只在同服务地址下共享。

B 站本期实现扫码登录窗口、账号核对、关键词搜索、视频介绍与首批评论阅读、模型总结/草稿，并按本轮新增需求补齐自动评论与回复一级评论。点赞、关注等操作仍拒绝；视频画面、音轨与字幕不在本期阅读范围。小红书保留原有功能，受警告后所有自动访问均阻断。B站扫码、绑定、搜索、介绍与首批评论读取、模型草稿和话题记忆已完成本机实测；结果与范围见末节。

## 社区依据

- [OpenCLI 的多平台适配器目录](https://github.com/jackwener/OpenCLI/blob/main/docs/adapters/index.md)：统一命令入口，平台保留自己的适配器。借鉴职责划分，不安装整个工具集或接管日常浏览器。
- [Bilibili MCP #84](https://github.com/XZXZZX-Ai/bilibili-mcp/issues/84)：已有登录信息未随请求传递会引起 412。读取必须使用当前独立浏览器的登录态；412 是访问受限信号，不直接宣称账号被封。
- [B站评论接口社区记录](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/comment/list.md)：新评论入口带 WBI 签名。执行器监听当前视频网页自身加载的首批评论响应并核对视频 `oid`，不额外请求旧接口；超时、目标不匹配均保留“评论未取得”。
- [小红书 #777](https://github.com/xpzouying/xiaohongshu-mcp/issues/777)、[#877](https://github.com/xpzouying/xiaohongshu-mcp/issues/877)：少量浏览仍有警告报告。频率是本机保护参数，不是平台许可，也没有已验证的安全阈值。
- [LINUX DO 模拟点击警告反馈](https://linux.do/t/topic/2589063?tl=en)：改为可见浏览器或模拟鼠标不能被宣传为免风控。

## 当前链路与最小改造

现状：SwiftUI / Web → `SocialControlServer` → 单个 `SocialEngine` → 模型或 `XiaohongshuAdapter` → 本机浏览器。帖子 URL、提示词、资源文案与侧栏均写死小红书；连续生成草稿没有阅读间隔。

用户选择平台。

→ 同一 `SocialControlServer` 按明确的平台标识路由到相应引擎，任务查询也按平台隔离。

→ `SocialEngine` 检查配置版本、账号、警告状态和阅读冷却，再调用共享浏览器进程包装器。

→ 固定平台的执行器使用自己的 Profile 和站点白名单，读取后返回统一帖子模型。B站仅在账号、视频、父评论、正文、截止时间匹配且许可未使用时放行一次评论 POST，其余写入阻断。

→ 同一模型和记忆代码生成总结或草稿，返回当前平台面板。不会读取其他平台的会话。

新增平台枚举仅承担当前两站真实存在的差异：名称、内容称呼、原文 URL、允许站点和写能力。新增平台集合仅承担实例、共享凭证和控制服务生命周期，不另建队列框架、插件系统或数据库。

## 契约与存储

`SocialCommand` 增加可选 `platform`；旧命令缺省仍指向小红书。`/api/status`、`/api/action`、`/api/job/<UUID>` 增加 `?platform=xiaohongshu|bilibili`。正文与查询平台不一致、未知平台、同编号更换平台/内容均拒绝；每个平台独立保存幂等任务状态。

调用方是原生内嵌页与本机 Web，接收方为 `SocialControlServer`。现有 Swift 输入类型如下；`revision` 在保存、登录、读帖等操作需要与当前状态一致，暂停与报告警告允许越过陈旧版本/忙状态立即生效。`key` 只用于配置凭证，不传入浏览器执行器。

```swift
struct SocialCommand: Codable {
    var requestID: UUID
    var action: String
    var revision: Int?
    var recordID: UUID?
    var hash: String?
    var content: String?
    var settings: SocialSettings?
    var expectedUID: String?
    var key: String?
    var persistKey: Bool?
    var acknowledge: Bool?
    var platform: SocialPlatform? // nil 保持小红书兼容；枚举仅 xiaohongshu / bilibili
}
```

请求示例：

```json
{"requestID":"00000000-0000-0000-0000-000000000001","platform":"bilibili","action":"search","revision":1}
```

输入携带 `X-Social-Control`，POST 还需同源 `Origin` 和 JSON 类型。动作返回 HTTP 202，输出按现有实现为 `[String: Any]` 的 JSON 对象；调用方按相同平台查询任务，不能把 HTTP 202 当完成。示例：

```json
{"requestID":"00000000-0000-0000-0000-000000000001","state":"pending"}
```

任务输出为 `{"state":"complete"}`、`{"state":"failed","error":"固定或经清理的用户提示"}` 或尚未结束的 `pending`；另一平台或不存在的任务返回 `unknown`。非法平台/正文不一致为 HTTP 400，授权/来源错误为 403，同 UUID 更换平台或内容为 409，任务表超过 200 且无法回收已结束项为 429。后端业务拒绝在任务的 `failed` 中返回；暂停、受限、登录错误与未知提交不自动重试。

状态增加 `platform`、`platforms`、`canWrite`、`warningAt`、`nextReadAt`、`recommendedSettings`；平台列表只含标识、名称和能力，不包含其他平台账号、记录或访问令牌。草稿中的帖子带可选平台标识；旧帖子缺省为小红书，B 站引擎拒绝小红书帖子。

设置增加可选 `readIntervalSeconds`，新配置默认 60 秒，范围 5–3600 秒；旧数据缺少该字段时仍按 30 秒兼容。它限制搜索/读帖开始的间隔，包括发送前重新读帖；账号核对和页面自带子资源不算单次阅读。连续浏览等候，手动操作过快则提示剩余时间，不自动重试。保存下次允许时间再访问，重启不能重置冷却。既有发送间隔仍独立生效。

状态增加可选 `warningAt`。执行器识别账号预警、验证码或访问限制时返回固定 `platform_restricted`；引擎暂停并持久化。用户也可手动标记收到警告，即使任务忙也能停止。暂停后只允许本地设置/草稿整理与查看记录；所有新的平台访问和模型生成被阻止。解除需要用户明确确认已在官方客户端处理，不清空发送未知状态和额度，不自动启动。

小红书沿用 `Social/social-state.json` 和原 Profile，不迁移、不重置；B 站使用其独立子目录。状态与登录文件保留已有本机权限。已在旧版本收到警告的本机升级时，写入一次性 `.platform-warning` 标记；新引擎在取得原状态锁后把它作为警告暂停条件，明确解除时才移除，不给所有旧用户统一增加警告。两站同号字符串也不共享记忆或额度。未知提交、冷却及警告跨重启保留。

## 默认自动运行 · 2026-10-28 增补

小红书和 B站新建配置都默认 `auto`。首次扫码、核对绑定和模型配置后，填写主题、保存并点「开始自动运行」，确认本轮范围即可。AI 自动搜索、阅读、补入本帖记忆、判断是否参与、生成短评、提交和核对；不需要逐条审核。`skip` 不发送，任务有限时，不自动续跑，也不监控全站通知。客户端与 Web 加载同一资源，行为一致。

| 设置 | 两站新配置默认值 |
| --- | --- |
| 主题 / 人格 | 独立游戏 / 大肥鱼，可自行修改 |
| 模式 / 话题记忆 | 自动运行 / 开启 |
| 本轮时长 / 阅读上限 | 15 分钟 / 5 条 |
| 本轮模型请求上限 | 5 次；摘要与评论合并一次生成 |
| 每日发送尝试上限 | 每个平台绑定账号 3 次；失败、未知也计入 |
| 搜索 / 读帖间隔 | 60 秒；发送前刷新与结果回读也受限 |
| 发送间隔 | 至少 300 秒 |
| 每条文字 | 最多 80 字 |

保存的旧设置保持原值，不静默把草稿模式改为自动。面板「使用推荐设置」从后端 `recommendedSettings` 填入模式、额度和启用记忆，保留用户主题、人格、模型地址/名称及凭证；点击保存后生效，不启动任务、不清零计数、不解除警告。每日额度已满时拒绝启动自动任务，运行中达到额度即结束，避免继续浪费模型请求。

B站发送协议依据[社区维护的原始接口记录](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/comment/action.md)，不是官方稳定 API 或免风控承诺。只向固定 `https://api.bilibili.com/x/v2/reply/add` 发一次表单 POST；`oid` 使用本次读页取得的 aid，`type=1`，顶层 `root/parent=0`，回复一级评论时两者必须等于精确父 ID。CSRF 仅在自有登录页面内取得并使用，不返回面板或模型。提交前再次核对绑定 UID、页面及内容指纹，浏览器路由校验实际请求的目标/正文/截止时间并消费一次许可，禁用 Service Worker 以避免绕过路由。点赞、关注、删除、投币等写入仍阻断。

平台返回成功码不足以记成功：还必须有精确且不丢精度的评论 ID，以及匹配的视频、账号、父评论和正文；否则为未知，保留额度并暂停，绝不自动补发。一级回复回读只取该根评论下一页内最多 20 项，未找到保持「平台已接受」；账号变化、验证或回读异常暂停后续任务。接受回执与警告同时到达时保留回执，再持久暂停，不能抹成“未发送”。

本机已经收到警告的小红书仍暂停；默认值改变不会解除。以上间隔是减少无谓请求的工程默认值，不能保证账号不受限制。

## 实施与验收

1. 泛化平台元数据、链接、引擎和控制路由，保留旧小红书数据兼容。
2. 新增 B站读写适配，复用 Node/Playwright 安装与进程包装；发送前原子预留、一次许可、精确回执与有限回读共用现有引擎。
3. 同步原生分类与共用 Web 选择器、能力提示、阅读间隔和警告操作。
4. 合成回归：旧数据、平台切换、临时 Key 地址隔离、同号记忆隔离、警告重启保留、暂停后迟到结果、两站自动运行、B站精确发送、阅读冷却、HTTP 鉴权和跨平台任务编号。
5. Node 页面夹具：B 站搜索/帖子/评论映射、错误与验证码不能当空结果；原有小红书出站评论契约继续通过。
6. 构建原生应用，检查原生和 Web 页面。QQ/微信既有测试继续执行。合成测试不得真实登录或发送。

实测暴露并修复了三处问题：登录父元素包含悬浮菜单，改为点击可见“登录”再点“立即登录”；后台社交入口遗漏了 QQ 已有的禁止不可见钥匙串弹窗设置，现复用同一启动保护；提示词曾无条件要求只总结，现按 `browse` / `review` / `auto` 明确参与方式，并回归验证浏览仍不能出稿。B站评论改为监听网页自身签名请求的首批响应并核对视频目标，不额外调用旧评论接口。

验收结束状态：B站 `running=false`、`busy=false`、发送尝试 0、未知提交 0，账号与话题记忆保留，本机面板可继续查看草稿。小红书已有警告的暂停与升级标记保留，本轮未真实访问；QQ / 微信运行未切换。主页面和 API 的访问受限信号均进入持久暂停，仍不承诺免风控或长期无故障。

登录失败只覆盖写一张本机诊断图和一份错误类型/来源域名记录，0600，最多保留这一组，不记录 Cookie、令牌、页面 HTML 或输入内容。原始失败、修复与验收证据保留于本机调研档案 `20261028-social-platforms`；公开文档和截图不包含真实账号、二维码、密钥或聊天记忆正文。

## 自动模式增补验证 · 2026-10-28

- `bash scripts/test.sh`：182 项 Swift 测试通过（105 项引擎 + 77 项 BotCore），含 18 项社交测试。新增两站自动运行到配额停止、额度用尽拒绝启动、旧草稿模式保存不被默认值覆盖，以及接受回执与警告并存的合成验证。
- Node 合成夹具运行真实页面回调及生产路由：固定目标表单、父评论、账号/内容/指纹变化、一次许可、重复字段、过期、暂停/受限、丢精度 ID、拒绝、验证码、断线不重试及精确回读通过。推荐设置只填任务字段、不改模型/主题的契约通过；小红书原有 11 项出站断言与页面读取/回读继续通过。
- `bash scripts/build.sh`、严格签名、打包后真实回环 HTTP 鉴权/来源/平台路由/推荐默认值和 QQ 零发送回归通过；公开文件隐私扫描通过。
- 真实 Chrome 点击「使用推荐设置」、保存，重新载入后自动模式与全部额度保留。后台确认未改变绑定或清零模型/发送记录。
- 更新前通过原生界面确认 QQ、微信、小红书均暂停，退出旧客户端与本轮独立社交 CLI，启动新版原生客户端，由同一进程持有两个平台。实际点击原生 B站入口、「浏览与回复」、推荐设置、保存，后台确认一致；不是仅渲染预览。未连接 QQ、访问微信或恢复小红书。
- 本机两站均 `mode=auto`、`running=false`、`busy=false`，当天发送尝试和未知均为 0，各保留一条话题记忆。小红书升级标记与持久警告保留，禁止启动；B站账号绑定保留。共享模型 Key 按此前授权仅配置在进程内存，重启后需重新配置或完成本机钥匙串授权。

本次没有访问真实社交内容、调用真实模型或发表评论；之前的 B站阅读/草稿证据仍有效，但新增自动发布仅有合成契约证据，尚不能宣称真实 B站发布或公开可见性已验收。旧截图保持原样，新的配置操作截图见[界面说明](SCREENSHOTS.md#自动运行默认配置--2026-10-28)。本节记录本机验收范围；源码同步到 GitHub 不代表发布安装包、云端部署或完成真实评论验收。
